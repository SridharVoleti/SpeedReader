## Status definitions (strict, issue #27)

- `IMPLEMENTED_TESTED`: the requirement is reachable through the intended production integration path, persists/authorizes correctly where required, and has automated evidence for that integrated path. Rows that are inherently process, document or absence checks (governance, no-billing, no-email, CLAUDE-*) are `IMPLEMENTED_TESTED` on their document/guard evidence and are marked as such in the notes.
- `PARTIAL`: domain-only or schema-only code, runtime wiring missing, fixture-only behaviour, or a dependency on an unwired production service. Never counted as complete.
- `BLOCKED_EXTERNAL`: cannot be completed or certified without something outside this repository (platform contract, hosted infrastructure, approved canonical content, an external QA gate).

### What is real vs. assumed
- The learner journey (`/`) runs on the v3 engine through `/api/v3/*`: assessment (server-timed, content from an approved manifest), one-word reader, questions, explanation (typed or spoken), feedback/Level Up, BPC, familiar practice, News Reader, spaced memory checks. Scoring and evidence are server-side only.
- Production content comes only from approved SR packages and an approved ASSESSMENT-MANIFEST. With none approved the journey fails closed with a friendly "being prepared" message. A labelled fixture exists only when diagnostics are enabled (tests).
- Production persistence fails closed: a Vercel production deployment without valid Supabase settings serves 503 (`/health` CONFIGURATION_ERROR). File adapters are for local/test/preview only.
- The Supabase schema (migrations 0001-0008) is verified against real Postgres (PGlite) incl. RLS on every table, atomic evidence projection, concurrency-safe sessions. It has not been applied to a hosted Supabase project.
- There is no production readiness runtime: readiness lifecycle, forms, recency and the P10 executor are domain code (see PARTIAL rows).

### Open items (why each non-complete row is not done)
1. **Readiness runtime absent** (APP-READY-001..007, APP-RECENCY-001..008, APP-KM-007/008, APP-DB-008, APP-API-003): the lifecycle is verified at domain level; nothing creates, serves or persists readiness streams in production. Needs an approved canonical rule table (below) before it is worth wiring.
2. **No approved canonical readiness rules** (APP-KM-004/006, BLOCKED_EXTERNAL): `lib/v2/p10-readiness.ts` runs the repo's Blocker-4 v1.0 table, flagged non-canonical; the v0.56 freeze-candidate differs in 7 of 15 rows.
3. **Production semantic evaluator not wired** (APP-COMP-008): only the deterministic derived-idea evaluator runs.
4. **Calibration publication not wired** (APP-DB-009) and **domain-only validators** (BPC style/fidelity, World 2-5 registry, level semantics, question alignment, free-explanation prompt, stamina validation, requirement-state registry).
5. **Platform/infra dependencies** (BLOCKED_EXTERNAL): `/identity` contract (PLAT-003), Android shell (INFRA-001), hosted Supabase/Vercel (INFRA-003), BabySteps accessibility QA gate (NFR-005); parent authorization scope (API-008, PARTIAL).
6. **Content authority**: must supply and approve the ASSESSMENT-MANIFEST (`<approved>/assessment/ASSESSMENT-MANIFEST.json`) and the packages it lists.
